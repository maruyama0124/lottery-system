# /pr-summary

## 概要
現在のブランチの変更内容を解析し、GitHub PR用のサマリを生成して `pr-summary.md` に出力する。

## 入力
- 第一引数: ベースブランチ名 (省略時は `main`)
- 現在のブランチの git log / git diff (自動取得)

## ワークフロー

1. **ベースブランチを決定**
   - 第一引数が指定されていればそれを使用
   - 指定がなければ `main` を使用
   - 以降 `<BASE>` は決定したベースブランチを指す

2. **変更内容を収集**
   ```bash
   git log <BASE>..HEAD --oneline
   git diff <BASE>..HEAD --stat
   git diff <BASE>..HEAD
   ```

3. **サマリを生成** (下記テンプレートに従う)

4. **ファイルに出力**
   - 出力先: `.tmp/{ブランチ名}-pr-summary.md` (プロジェクトルート)
   - 既存ファイルは上書き

## テンプレート

```markdown
## 概要

<!-- なぜこのPRが必要か・何を解決するかを1〜3行で -->

## 主な変更点

-

## 動作確認

-

## 影響範囲

-

## 関連

-
```

## 生成ルール

- **文体**: 言い切り形。「〜した」「〜を追加」「〜を修正」
- **概要**: 背景・目的を書く。実装詳細は書かない
- **主な変更点**: ファイル単位でなく機能・責務単位でまとめる
- **動作確認**: コマンド例や操作手順など具体的に書く
- **影響範囲**: Breaking change は ⚠️ を付けて強調する。なければ「なし」
- **関連**: 関連issueがあれば `Closes #123` 形式で記載。なければ省略
